# 安全设计

## 可以防护

- 单独复制 `vault.enc` 后直接读取快捷词、服务器信息或密码。
- 不同 expand 本地用户误看、误改彼此的数据。
- 将个人快捷内容误提交进 Git。
- 列表接口意外返回独立秘密值。
- 用户离开电脑后加密库长期保持解锁。

## 不能防护

- 已控制当前 Windows 会话的恶意软件。
- 管理员读取应用内存、记录键盘或截屏。
- 同一个系统账号下删除、替换其他用户的加密文件。
- Windows 剪贴板历史或第三方剪贴板管理器留存副本。

多人需要强隔离时，应分别使用 Windows 系统账号；expand 本地用户不是操作系统安全边界。

## 加密参数

- Argon2id：默认 64 MiB、3 次迭代、2 线程。
- 载荷：AES-256-GCM。
- 每个本地用户独立 Salt、数据密钥和随机 Nonce。
- 主密码不保存；数据密钥由主密码派生密钥包装。
- 加密文件读取上限为 32 MiB，并校验 KDF 参数范围。

## 使用规则

- MySQL 等连接实例可以保存密码，但默认生成的替换文本不包含密码。
- 独立秘密列表不返回秘密值；值只能通过限时复制接口读取。
- 普通快捷词如果被标记为敏感，仍会在用户明确触发时替换到目标输入框，因此不要把密码直接写进普通替换内容。
- 不在日志中记录主密码、秘密值、完整快捷内容或剪贴板内容。
- 前端异常日志在落盘前会脱敏常见密码、Token、Cookie、Authorization 和带密码 DSN；仍不建议把秘密写进异常文本。
- `vault.enc` 可以备份，但应通过不同渠道保管主密码。
- 忘记主密码后无法恢复。

## 当前限制

- 没有 Windows Hello 或硬件密钥解锁。
- 快捷词展开使用 Windows 直接文本输入，不经过剪贴板；独立的“复制秘密”功能仍然使用剪贴板。
- 没有 SSH Agent 集成。
- 没有主密码修改和恢复流程。
- 尚未经过独立密码学安全审计。
